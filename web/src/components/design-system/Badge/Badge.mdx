# Picking a `Badge` colour

Pick the family by the badge's job, then the value inside it. Never pick a colour for decoration. Between `outline` and `filled`, the notes below are a recommendation, not a rule: pick the one that reads best where the badge sits.

- **Neutral**
  - `outline` (default): border, no fill. Light; reads as a label. Suits a badge on its own or beside text: titles, headers, menus.
  - `filled`: grey fill, no border. Reads as one block, so a column of them scans easily, and it stays visible on hovered and selected rows. Suits tables and dense lists.
  - `inverted`: solid dark fill. One strong marker per surface, e.g. a version next to a title.
- **Status**: `error`, `warning`, `success`, `info`. Hue fill, same-hue hairline. A state: failing, degraded, healthy.
- **Category**: `violet`, `blue`, `teal`, `green`, `amber`, `pink`. Hue tint, same-hue hairline and text. Telling categories apart.

## Rules

- Every badge renders in mono; there is no font option.
- Badge text keeps the case it is written in; there is no caps option.
- Borderless inline metrics and links are not badges: use `Metric`.
- Need custom content inside the box? Use `BadgeShell` with the same `color` and `size`.
- Do not add a colour for one call site. If no family fits, extend a family in `Badge.tsx` and this page together.
