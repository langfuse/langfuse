## Setup / prerequisites

- Chromium: the staged `.ds-sync` playwright can need a newer headless shell than the preinstalled one (`[RENDER_SKIPPED] ... Executable doesn't exist at /opt/pw-browsers/chromium_headless_shell-<rev>`) - run `(cd .ds-sync && npx playwright install chromium)`.

- Env: build Storybook with the committed `.env.dev.example` (`npx dotenv -e ../.env.dev.example`), never the main checkout's `.env` (may hold secrets). `gen-entry.sh` mirrors its `NEXT_PUBLIC_*` values into `process-shim.js`.
- Build `@langfuse/shared` first (`pnpm --filter=@langfuse/shared exec prisma generate && pnpm --filter=@langfuse/shared build`) - the bundle resolves its `dist/`; missing dist = WORKSPACE_SIBLING failures.
- `.design-sync/node_modules` must be a symlink to `../.ds-sync/node_modules` (gitignored; recreate per clone) - `overrides/dts.mjs` needs ts-morph from there.
- The design system has no `dist/`: `.design-sync/ds-package/` is a shim package. `gen-entry.sh` regenerates `index.ts` (one `export *` per public module, `process-shim.js` imported first) - rerun it when components are added/removed (buildCmd does).

## Build fixes (why each file exists)

- `ds-package/tsconfig.json`: maps node builtins `fs`/`stream`/`zlib` -> `node-stubs/empty.js` (Next's bloom-filter pulls gzip-size on a dev-only branch) + `"jsx": "react-jsx"`, and `next/router` -> `next-router.ts` (see Router). Gotchas: the converter's comment stripper breaks on a `"//"` JSON key - no comments/"//" keys; do NOT map `@/*` there (the paths plugin's existsSync matches directories and breaks directory imports) - esbuild handles `@/` via web/tsconfig.json natively.
- `process-shim.js` (generated): Next/next-auth/env.mjs read `process.env` at module scope -> "process is not defined" without it.
- `ds-package/copy-css.sh`: Tailwind v4 CSS only exists compiled inside the Storybook build; copies the stylesheet `sb-reference/iframe.html` links to `ds-package/storybook-compiled.css` (cfg.cssEntry, gitignored). Also injects IBM Plex Mono `@font-face` into `sb-reference/iframe.html` (see Fonts).
- `ds-package/LangfuseProvider.tsx` (cfg.provider): the decorator auto-bundle fails (`Could not resolve tailwindcss`), so the preview.tsx decorator chain is distilled here: RouterContext(stub) > LayerProvider > ThemeProvider(light, class) > `#__next` bg/text > SessionProvider(null) > TooltipProvider.
- Router: Storybook's nextjs-vite framework mocks the Pages router; table code (`data-table.tsx` rows, `peek.tsx`, `ValueCell.tsx`) calls `useRouter()` from `next/router` and threw "NextRouter was not mounted" (blank Table previews). LangfuseProvider mounts an inert stub router. Each `_preview/<Name>.js` bundles its OWN copy of non-DS code (web/src/components/table, next), so a context from the bundle alone never reaches it: tsconfig maps `next/router` -> `ds-package/next-router.ts`, whose `useRouter` reads the RouterContext LangfuseProvider publishes on `globalThis.__dsRouterContext`. tsconfig is not grade-keyed, so this carried grades.
- `#__next` height: Storybook gives `div#__next` `height: 100vh` in canvas view so globals.css' `#__next, #__next > div {height:100%}` chain resolves (IOTableCell panels, truncation footers). LangfuseProvider's `fullHeight` prop mirrors it, defaulting on only for `?story=` captures (grid cards and designs stay `auto`; designs can pass `fullHeight`).
- Public assets: LangfuseIcon/LangfuseLogo load `${NEXT_PUBLIC_BASE_PATH ?? ""}/icon.svg|wordart-*.svg` from web/public. The bundle ships no loose files (the build wipes ds-bundle/), so `gen-entry.sh` discovers those paths in DS sources and generates `public-assets.js` (data URLs + an `<img src>` remap via `setAttribute`/`src` setter), imported right after process-shim.js. The reference was broken too - `.ds-sync/storybook/http-serve.mjs` serves `.svg` as octet-stream - so copy-css.sh injects the same script into `sb-reference/iframe.html` (`data-ds-sync-assets`, replaced each run). Run gen-entry.sh before copy-css.sh.
- `ds-package/csf-factories-preview.tsx` + `overrides/story-imports.mjs`: stories use CSF factories (`preview.meta().story()`), which need Storybook's runtime ("definePreview is not a function"). The fork redirects `web/.storybook/preview.*` to the shim, which flattens factory stories to CSF3 and maps `globals.theme === "dark"` to a `.dark` wrapper div. It also runs meta + story `beforeEach` hooks once before first render (cleanup on unmount): AppSidebar's Launch Week stories pin `Date.now` there, and without it the frozen capture clock expired those notifications.
- `overrides/dts.mjs`: ts-morph `.d.ts` extraction for TS source (baseUrl web + `@/*`, @types/react from web/node_modules, resolveSourceFileDependencies). Two forks for the shared components: `pkgDir` is `web/src` (not the design-system dir), so their own `on*` callbacks survive the DOM-noise filter; and `propsBodyFor` looks up `<Name>Props` in the component's own file first, because with the wider `pkgDir` another file's `InputProps` was winning.
- `cfg.storyImports.shim` lists the shared modules whose filename doesn't match the export (`drawer.tsx`, `MarkdownViewer.tsx`) plus `ui/sidebar.tsx`. Without the shim the preview bundles a second source copy, which loses LangfuseProvider's contexts ("`Tooltip` must be used within `TooltipProvider`", "useSidebar must be used within a Sidebar"). Modules whose filename matches their export (`ScoreTag.tsx`, and since 2026-10-22 `ui/AIAssistedInput.tsx`, `GroupedScoreBadges.tsx`, `layouts/MobilePageActionsContent.tsx` - renamed from kebab-case upstream) redirect to the bundle without a shim entry. The shim list still carries the dead `ai-assisted-input.tsx`/`grouped-score-badge.tsx` patterns (they match nothing): `cfg.storyImports` is in the GLOBAL grade key, so editing it re-grades all ~82 components - drop them only when a global re-grade happens anyway. gen-entry.sh also exports `SCORE_LEVEL_LABELS`, which `ScoreTag.stories.tsx` imports (without it: `Cannot convert undefined or null to object`, empty ScoreTag card). A story importing a non-component name from a module whose filename matches its export needs that name in gen-entry.sh.
- MobilePageActionsContent (2026-10-22): after the rename it redirects to the bundle, while its story's `<Popover>` (ui/popover, lowercase filename -> never shimmed) bundled a second copy -> "`PopoverPortal` must be used within `Popover`". Fix without touching the global key: gen-entry.sh exports ui `Popover`, `PopoverTrigger` (no DS name clash; the design agent needs them to open MobilePageActionsContent anyway), and owned `previews/MobilePageActionsContent.tsx` mirrors the story importing both from the package.
- `SidebarProvider` + `SidebarInset` are exported because `AppSidebar` can't render outside them.

## Fonts

- Sans = system stack by design (globals.css `--font-sans`), nothing to ship.
- Mono = IBM Plex Mono, self-hosted at `web/public/fonts/*.woff2` and loaded in the app by `next/font/local` (`web/src/styles/fonts.ts`, var `--font-plex-mono`). Outside Next the var is unset and `font-mono` falls back to the literal "IBM Plex Mono" family, so `ds-package/plex-mono.css` (cfg.extraFonts) declares that family; copy-css.sh injects the same faces into the reference iframe so compare verifies with the real font. Keep both in sync with fonts.ts weights (400, 600).

## Preview / grading decisions

- `[PORTAL?]` fires on EVERY component - false positive: LayerProvider always mounts `div[data-overlay-root]` with empty layer divs as a body child. Judge overlay bleed from the images; apply cardMode "single" only where overlay content visibly escapes.
- `play()` stories: Storybook runs a story's `play` before capture; static previews never do. Stories whose post-play state differs visibly (opened dialog/menu/tooltip, toggled format) are skipped via `cfg.overrides.<Name>.skip` - they're interaction tests, not design variants. `(Test)` stories whose play leaves the initial render unchanged stay and are graded. Skips live in `cfg.overrides.<Name>.skip` (overlays: every (Test) story that opens a menu/hover card/tooltip/dialog; charts: (Test) stories whose play opens a tooltip or toggles a series; Dialog/Avatar/Codeblock interaction tests (incl. Dialog "(Test) Scrollable body keeps controls above footer", which opens the dialog); GroupedScoreBadges "(Test) With Overflow", KeyValueFilterBuilder "(Test) Observed Key Suggestion Preserves Value", MarkdownView "(Test) Reveals Header Controls On Focus"). A play() that only leaves a focus ring (Accordion/Alert/Callout dismiss tests, chart legend buttons, IconButton/Toggle clicks, form-input (Test) stories, Table actions trigger, AIAssistedInput retrigger) is graded match - focus residue is not a design difference.
- Button absorbs 7 `Playground/Button` stories from `src/components/ui/Button.stories.tsx` (out of scope) - skipped by id.
- Table absorbs ~88 `Table/Columns/create*TableColumn` stories (titleParts match "Table"; titleMap can't exclude) - kept under Table with cardMode single, primaryStory Default.
- Avatar: owned `previews/Avatar.tsx` - Default story's `src: "/apple-touch-icon.png"` is a Storybook staticDirs path; the owned preview imports the file (esbuild dataurl) instead.
- Dark-theme stories (StatusMessage Dark*): Storybook paints the whole canvas dark, the preview only wraps the component - framing only, graded match.
- `layout: "fullscreen"` stories (charts, Dialog, Table, PaginationBar, IOTableCell): the card html keeps `body{padding:24px}` on `?story=` captures, so `h-dvh` story roots overflowed the 900x700 capture and lost the x-axis/legend band. `csf-factories-preview.tsx` appends a `FullscreenFrame` decorator to fullscreen stories that zeroes body padding on `?story=` captures only (grid/column cards keep padding).
- Grade-key gotcha: grade keys hash `overrides/*.mjs` fork bytes (any fork edit re-grades EVERY component) but NOT `ds-package/` sources. After editing the shim/provider, delete `.design-sync/.cache/compare/<Name>.grade.json` for the components whose render actually changes.
- Table name collisions: Table absorbs ~22 column-story files whose names repeat (19x "Default", 19x "Loading", 16x "Empty Value", ...). grade.json is keyed by story NAME, so one verdict covers every same-named story - judge each pair, record the worst verdict per name.
- Screenshot lifetime: package-build wipes `ds-bundle/_screenshots/compare/`, and EVERY compare run (scoped or not) replaces that folder with only its own captures. Finish all grading of one capture pass before the next build/compare; grades in `.cache/compare/*.grade.json` survive either way.
- Story caps: compare defaults to 20 stories per component - run Table with `--max-stories 120` and Tabs with `--max-stories 24` or tail stories stay ungraded.
- PaginationBar: its only offset-mode story "(Test) Navigates pages" (id `...--default`) is play-state and skipped, so offset-mode chrome is unverified; only the cursor-mode story is graded.
- Padded-layout framing: sb captures crop to the 868px story root at 0,0; ds captures are 900px with the card's 24px body inset, so full-width content is 16px narrower in ds. Framing only - graded match everywhere (Tabs, CodeSection, Button, Table columns, ...).
- Meta decorators apply twice (fixed, 2026-10-18): `makeStory` in `csf-factories-preview.tsx` merges meta decorators into `story.decorators`, and the preview generator (`preview-gen-storybook.mjs:60`) concatenates `meta.decorators` again, which doubled the `p-4` inset on DataTable and the 8 charts. `preview.meta` now omits `decorators` from the meta fields it returns. The 9 components were regraded after the fix and are pixel-identical apart from play() focus residue. The shim is not grade-keyed, so any later shim edit needs the affected grade.json files deleted by hand.
- Table Actor/Button column stories don't set `layout: "fullscreen"`, so the preview keeps the 24px card inset storybook lacks - framing only, graded match.
- SortableList is excluded (`cfg.titleMap {SortableList: null}`; still in the bundle via the design-system `export *`): both stories are play() tests - "(Test) Sorting Inside a Dialog" ends with the dialog closed, "(Test) Different Height Rows..." ends with the rows visibly reordered in storybook - so no static story can be verified. Drop the titleMap entry once a story without play() exists.
- ChartTooltip (`internal/charts`) is excluded (`cfg.titleMap {ChartTooltip: null}` + not exported by gen-entry.sh): all 10 stories render the tooltip only after play() hover/focus; charts render it internally.
- ConfirmationDialogController: the converter pairs stories to exports by display name first, so stories "Standard"/"Type to confirm" (exports `StandardExample`/`TypeToConfirmExample`) render the `(Test)` exports `Standard`/`TypeToConfirm` - identical args, so harmless; both `(Test)` stories are skipped. Revisit if their args diverge.
- OrganizationDropdownMenu/ProjectDropdownMenu: no story opens the menu (render-prop trigger, no `open`/play), so compare verifies only the trigger; the menu content is unverified.
- MediaTag "Wikimedia File Page Fallback" loads a commons.wikimedia.org URL, which the capture sandbox blocks - both panels show "Failed to load media", so that story is unverified. Re-capture unsandboxed (`compare.mjs --components MediaTag --force`) to verify it.
- Drawer Compact: the sb shot crops 16px into the fixed full-width sheet (hides its left padding/rounded corner) - framing only, graded match.
- Grading triage: `md5 -q` on each raw `__sb.png`/`__ds.png` pair separates byte-identical pairs from ones needing a careful look (still open one pair per story file to rule out both-blank) - a triage aid, never the verdict.
- ExpandToggle "(Test) Flips label and aria-expanded" is skipped by id (2026-10-25): its play() flips the toggle to "Show less".
- Avatar `TintedFallback` story (added upstream): the owned `previews/Avatar.tsx` needs one export per story, in story order. A missing export pairs stories by order, so "Tinted Fallback" rendered the `(Test)` hover story. Add an export whenever Avatar gains a story.
- ExpandToggle (added 2026-10-25): `cardMode: "column"` for `[GRID_OVERFLOW] wide` on Overview.

## Re-sync risks (check these first when a re-sync diverges)

- Order: `@langfuse/shared` build -> Storybook build under `.env.dev.example` -> `gen-entry.sh` -> `copy-css.sh` (re-injects fonts + public assets into `sb-reference/iframe.html`; a fresh Storybook build drops both) -> package-build.
- `ds-package/` sources (LangfuseProvider, next-router.ts, csf-factories-preview.tsx incl. FullscreenFrame, process-shim/public-assets generation, tsconfig) are NOT grade-keyed: after editing them, delete the affected `.cache/compare/<Name>.grade.json` by hand.
- `overrides/story-imports.mjs` IS keyed: any byte change re-grades all 80 components.
- process-shim.js mirrors `.env.dev.example` NEXT_PUBLIC_* values; if a value there starts gating a component's render, the preview follows the dev example, not prod.
- New web/public assets referenced via `NEXT_PUBLIC_BASE_PATH ?? ""}/...` are picked up by gen-entry.sh automatically; other static paths (e.g. Avatar's `/apple-touch-icon.png`) need an owned preview.
- Shared app components: a new kebab-named (or otherwise export-mismatched) module a story imports must join `cfg.storyImports.shim`, or its preview bundles a second copy and loses provider contexts. New shared components also need a line in gen-entry.sh's heredoc. MediaTag's Wikimedia story stays unverified while capture runs sandboxed.
- Owned previews: `previews/Avatar.tsx` and `previews/MobilePageActionsContent.tsx` shadow the generated ones - re-check them when those stories change (`[STORY_CHANGED]`).
- DateRangeInput (added 2026-10-22): all four `(Test)` stories open the popover in play() -> skipped by id; the three `features-evaluations-...-daterangeinput--*` stories (an out-of-scope `web/src/features` component of the same name, whose props differ -> `Cannot read properties of undefined (reading 'find')`) are skipped by id too. Only `Default` (closed trigger) is graded; popover content is unverified.
- Upstream file renames break gen-entry.sh's explicit shared list first (`[UNRESOLVED_IMPORT] ... missing from node_modules` from `ds-package/index.ts`): update the module path there and re-run gen-entry.sh - the driver does NOT run `buildCmd`.
- Story `beforeEach` runs in the preview shim (see Build fixes); a story relying on Storybook loaders, `mount`, or async `beforeEach` work will still diverge.
- Late mount (2026-10-19): `_preview/Table.js` and `_preview/DataTable.js` are ~4.8MB (zod, `@langfuse/shared` dist, posthog, next) and finish executing ~1s after `networkidle`. Validate then fails `[RENDER] ... root empty` and compare reports every story `unpaired`, although the cards render fine. The fix is a local wait in the staged harness (lost on every restage - re-apply after the `cp -r`): in `.ds-sync/package-validate.mjs` before the big `page.evaluate`, `await page.waitForFunction(() => [...document.querySelectorAll('#root, [id^="r"]')].some((r) => r.innerHTML.trim().length), null, { timeout: 15_000 }).catch(() => {})`; in `.ds-sync/storybook/compare.mjs` wait for `Array.isArray(window.__dsCells)` before the pairing `evaluate`, and for `#r0` content in `storyShot` before `settleRender`. Better long-term: shrink those previews (they pull the server-side shared barrel). Still required on 2026-10-29 (previews now ~5.4MB; without the waits validate failed on Table in 3 of 3 runs).
- The driver applies `--max-stories` to every component; without it Table/DataTable are capped at 6 stories. Run compare for Table (`--max-stories 120`) and DataTable (`--max-stories 20`) separately when they are in scope.
- Play-state skips are by story id; renamed stories silently lose their skip (compare then shows the post-play delta - re-skip).
- Story caps (Table 120, Tabs 24), Table name collisions, ConfirmationDialogController pairing and HoverCard "(Test) Delayed" timing (see above).
- A new Storybook framework mock (router, image, font) is invisible to the bundle - a blank or throwing preview usually means one is missing from LangfuseProvider.
- Previews compile with esbuild `charset: 'utf8'`, so a `"\uFFFD"` string constant anywhere in the import graph lands as a raw U+FFFD and claude.ai flags the file as having unreadable characters. Check with `perl -CSD -ne 'print "$ARGV\n" if /\x{FFFD}/' ds-bundle/_preview/*.js`; fix at the source (e.g. `String.fromCharCode(0xfffd)`, as in `packages/shared/src/domain/auditLogs.ts`).
- Anchor global-key mismatch (2026-10-29): the uploaded `_ds_sync.json` had sourceKeys for all 85 components that differ from a build of `main`'s committed `.design-sync/` (same keyRecipe 7, scriptsSha cca50c6b4bf08bb1 -> 77113bc9d026db83), so every component is `changed` and needs a full re-grade on the next passing run. Likely cause: the last upload ran with config/fork bytes that never landed on `main`. Grade the whole roster once (primary-story sampling per the skill) and upload; the anchor then matches `main`.
- MobilePageActionsContent (2026-10-29): upstream added a "Menu rows" story (HeaderActionMenuRow + DS Badge) and wrapped both stories in `flex justify-end p-3` with `layout: "fullscreen"`. The owned preview now mirrors both, in story order. Not yet graded - capture never ran.
