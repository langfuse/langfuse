# Bedrock embedding quality for Topics

Research date: 2026-09-23. Scope: model quality, representation settings, API limits. Regional availability, prices, retention and account entitlement are covered separately. No application changes, paid inference or customer-data processing were performed.

## Decision

**Cohere Embed v4 is a reasonable first candidate, not a demonstrated clustering winner. Include Cohere Embed English v3 as a serious challenger and Titan Text Embeddings V2 as the cost baseline.** Nova Multimodal Embeddings is also technically suitable and must not be omitted from a current Bedrock inventory, but public evidence does not establish that it wins English topic clustering.

The task is symmetric: short English facet summaries are clustered, cluster centroids are formed, and future summaries are compared with those centroids. Neither multilingual retrieval scores nor support for long documents/images directly proves quality on this task. The original [MTEB paper](https://arxiv.org/abs/2210.07316) explicitly motivates evaluation across different embedding tasks rather than transferring conclusions from a single task.

For an initial v4 evaluation, use `cohere.embed-v4:0`, `input_type: "clustering"`, `embedding_types: ["float"]`, `output_dimension: 1024`, `truncate: "NONE"`. Evaluate 1536 dimensions too if quality is the priority. Choosing 1024 initially is an engineering tradeoff, not a published claim that it matches 1536 for Topics. The [Bedrock v4 API](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-embed-v4.html) supports these values; [Cohere's documentation](https://docs.cohere.com/docs/embeddings) recommends the clustering input type for clustering.

## What the primary benchmarks actually establish

### Direct clustering evidence: English v3 versus Titan V2

I downloaded the published result JSON from the benchmark maintainers' [MTEB results repository](https://github.com/embeddings-benchmark/results) and recomputed the arithmetic mean over the same 11 legacy English clustering tasks. This was arithmetic over existing results, not new model inference.

Snapshot: repository commit `fe1eb0571d7c1c261d3cb892c558477451ba5232`.

| Model                                         | Dimensions in result metadata | Mean V-measure, 11 tasks, scaled 0–100 |
| --------------------------------------------- | ----------------------------- | -------------------------------------- |
| Cohere Embed English v3                       | 1024                          | **47.43**                              |
| Titan Text Embeddings V2                      | 1024                          | **40.40**                              |
| OpenAI text-embedding-3-small, reference only | 1536                          | 46.65                                  |

Cohere English v3 exceeds Titan V2 on all eleven included tasks. Their dataset revision hashes match for every task. The result records do not retain the MTEB version or full invocation configuration, so this is comparable published evidence, not a controlled fresh experiment. The OpenAI result files lack dataset revision hashes and use 1536 dimensions, while Topics currently uses 768; do not treat that row as a precise comparison with the current deployment.

Pinned result directories: [Cohere English v3](https://github.com/embeddings-benchmark/results/tree/fe1eb0571d7c1c261d3cb892c558477451ba5232/results/Cohere__Cohere-embed-english-v3.0/external), [Titan V2](https://github.com/embeddings-benchmark/results/tree/fe1eb0571d7c1c261d3cb892c558477451ba5232/results/amazon__Titan-text-embeddings-v2/external), [OpenAI small](https://github.com/embeddings-benchmark/results/tree/fe1eb0571d7c1c261d3cb892c558477451ba5232/results/openai__text-embedding-3-small/1).

Tasks: ArxivClusteringP2P, ArxivClusteringS2S, BiorxivClusteringP2P, BiorxivClusteringS2S, MedrxivClusteringP2P, MedrxivClusteringS2S, RedditClustering, RedditClusteringP2P, StackExchangeClustering, StackExchangeClusteringP2P, TwentyNewsgroupsClustering. Reproduction: read each JSON's `scores.test[0].v_measure` (or legacy `test.v_measure`), average the eleven values, multiply by 100. No inference credentials required.

### Missing evidence for v4 and Nova

The inspected [Cohere v4 result directory](https://github.com/embeddings-benchmark/results/tree/fe1eb0571d7c1c261d3cb892c558477451ba5232/results/Cohere__Cohere-embed-v4.0/1) contains 33 retrieval task results plus model metadata and **no clustering results**. Cohere's [v4 announcement](https://docs.cohere.com/changelog/embed-multimodal-v4) describes improvements in text/image/mixed retrieval, not a measured English-clustering win over v3.

Amazon's [Nova technical report](https://cdn.amazon.science/ba/f2/d0af272848748a24ba6ba45af3a7/nova-mme-technical-report-14.pdf) reports multilingual text retrieval NDCG@10 of 63.8 at 3072 dimensions, versus Titan V2 at 58.3. Nova's 1024-dimensional version scores 62.9. The report focuses on retrieval; it does not publish an English-clustering comparison. Its Cohere v4 text benchmark entry is unavailable, so the report does not demonstrate Nova beating v4 in text retrieval either. Its image/document wins are not evidence for this Topics workload.

Consequently, a claim that v4 is objectively the best Bedrock model for Topics would overstate the evidence. The defensible outcome is a preferred candidate plus a small, task-specific comparison.

## Representation and throughput decisions

- **One embedding task mode throughout:** use `clustering` for both discovery summaries and future summaries assigned to those centroids. A later assignment operation is called classification in product terms, but its geometry still belongs to the space used to build the centroids. Do not switch future summaries to `classification` or `search_query`. This is a pipeline inference supported by the [Cohere warning against mixing input types](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-embed-v3.html). For Nova, the corresponding setting is `CLUSTERING`, which AWS specifically associates with forming cluster centers in its [practical guide](https://aws.amazon.com/blogs/machine-learning/a-practical-guide-to-amazon-nova-multimodal-embeddings/).
- **Float vectors first:** current numerical clustering consumes floating-point vectors. Quantized/binary outputs need a separate quality and distance review; they are not a drop-in optimization.
- **Normalize consistently:** Titan V2 exposes `normalize`, default true. Cohere and Nova expose no equivalent switch in the cited Bedrock schemas. Do not assume a unit-vector guarantee without checking; validate finite, nonzero vectors, then apply the pipeline's L2 normalization and centroid-normalization convention consistently. This recommendation is numerical compatibility guidance, not an assertion that Cohere/Nova outputs are unnormalized.
- **Batching is meaningful for short summaries:** Cohere permits up to 96 texts in one synchronous call; Titan and Nova accept one text input per synchronous request. AWS documents embedding-model capacity in requests per minute in its [Titan guide](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html). Batching can reduce request overhead and quota pressure, but it does not prove lower latency or higher account throughput. Measure actual regional quotas and p95 latency. Provider tokenizers differ; OpenAI `cl100k_base` is not an authoritative Cohere/Nova token counter.
- **No silent truncation:** `NONE` makes unexpectedly long summaries fail visibly. v3's 512-token limit is adequate for many 100-word English summaries but is stricter than the pipeline's existing 1024-token input guard.
- **Embedding identity includes settings:** record provider/model, dimensions, input purpose and normalization behavior. Same dimensions do not mean interchangeable vectors. A model change requires re-embedding and rebuilding centroids/maps; similarity and outlier thresholds need recalibration.

## Minimal comparison that answers our actual question

Freeze a representative set of English facet summaries before changing the summarizer. Compare v4 at 1024/1536, English v3 at 1024, and Titan V2 at 1024, holding the downstream clustering algorithm constant for the first pass. Include paraphrases, near-neighbor topics, rare topics, ambiguous/multi-intent summaries, IDs and numerical differences. Review cluster coherence and incorrect merges, then test future-summary assignment against held-out examples. Use labeled pairwise precision/recall or ARI/NMI when labels are available, alongside coverage, outlier rate, stability across resampling, latency and cost. Recalibrate thresholds per model after the first pass. Silhouette score alone is not a cross-model quality verdict because each model defines a different geometry.

Keep summarizer-model changes separate from the embedding comparison; otherwise a better or worse summary can be mistaken for an embedding effect. This comparison has not been run.

## Licensing

The main candidates are proprietary managed models, not OSS embedding weights. AWS explicitly calls Nova proprietary in its [service card](https://docs.aws.amazon.com/ai/responsible-ai/nova-multimodal-embeddings/overview.html). Amazon's [Titan model card](https://huggingface.co/amazon/Titan-text-embeddings-v2) contains results/examples and lists Amazon service terms; it is not a downloadable weight release. Cohere's [private deployment instructions](https://docs.cohere.com/docs/single-container-on-private-clouds) require a Cohere-issued license to pull its containers. Bedrock hosting and data-retention terms are separate from model openness.
