# Theme Lab

In dev, prefer the in-app panel (`web/src/features/theme-lab/`, enable with `themeLab.enable()` in the console) — the files here are the standalone console/bookmarklet fallback for non-dev contexts and must stay semantically in sync with it.

Injectable docked side drawer (right edge, full height, overlays the page — no layout shift; resizable 260–560px via its left edge, collapsible to a slim clickable rail via the header chevron, width/collapsed persisted; Reset/Copy CSS pinned at the bottom; all panel chrome in a hardcoded monospace stack, independent of the tokens being tuned) for tuning the theme live on localhost:3000 (light or dark), in four collapsible sections. Every color row has an 18px swatch showing its current color and a muted second-line readout of the raw `H S% L%` triplet exactly as Copy CSS emits it (paste-ready; when overridden, the row tooltip shows the stylesheet baseline as `code: <triplet>`); clicking it opens the native color picker (Chrome's includes an eyedropper) — accent rows take the full H/S/L (H integer, S/L one decimal), surface-ladder and text rows apply lightness only (hue/sat fixed by design, see tooltips), and accent L sliders get a hue-tinted black-to-white gradient track. A class observer on `<html>` swaps the mode-scoped sections (text + accent colors) when the app theme flips: old inline overrides are dropped, baselines recaptured, and the new mode's stored set re-applied (ladder/typography stay mode-agnostic; ladder is dark-tuning oriented). "Surface ladder" (expanded): `--header`/`--sidebar-background`, `--background`, `--card`, `--modal`, `--popover`, `--border` + secondary tokens, set inline on `<html>`, with live pp gaps (<1.5pp / ordering warnings) and v1 / v2 / pre-PR presets. "Typography" (collapsed): three-way font pairing (App default / Inter / IBM Plex; forced pairings auto-load missing faces from Google Fonts via exact-family checks and set `--font-weight-bold` inline — 600 for Inter, 500 for Plex, shown as a "bold: N" hint; pairing selection wins over any earlier bold override) plus per-row size sliders editing REM directly (0.5–2.5, step 0.025, live px hint) and a font-weight picker (– / 400–700) for the seven `--text-*` tokens — what you tune is exactly what lands in globals.css. The picker's default option shows the dominant rendered weight sampled from live `.text-*` elements (`– (400)`, `– (400*)` when mixed, full tally in the tooltip); "rescan" in the section header re-samples after navigation. "Text colors" (collapsed): lightness sliders for `--foreground`, `--muted-foreground`, `--foreground-tertiary`, `--sidebar-foreground`, `--link`, `--link-hover` with a live WCAG contrast ratio per row (vs `--background`, or `--sidebar-background` for the sidebar row; green ≥4.5, amber ≥3, red below) that tracks ladder edits; values persist per light/dark mode and only the set matching the page's mode is applied. "Accent colors" (collapsed): full H/S/L number inputs (plus an L slider) for `--primary-accent`, `--accent`/`--accent-foreground`, `--ring`, `--sidebar-accent`/`--sidebar-accent-foreground`, with WCAG readouts vs `--background` (primary, ring) or vs the paired fill (foregrounds; recomputed when either side changes); same per-mode persistence.

Because `--text-*` are Tailwind v4 `@theme inline` tokens compiled to literal font-sizes, typography overrides go through an injected `<style id="theme-lab-typography">` tag with `!important` rem rules (size + weight merged per `.text-*` rule), not custom properties. Copy CSS emits changed ladder tokens as globals.css HSL lines plus a commented typography block: changed `--text-*` tokens in rem exactly as displayed, `/* text-<name>: weight N */` notes (weights aren't globals.css tokens today), and a `/* pairing: IBM Plex */` marker — plus `/* text colors (dark|light) */` and `/* accent colors (dark|light) */` blocks with full `H S% L%` triplets noting the mode they were tuned in.

Three ways to run it:
1. Paste the contents of `theme-lab.js` into the DevTools console.
2. Save `theme-lab-bookmarklet.txt` (one line) as a bookmark URL and click it.
3. Have an agent inject it via the chrome-devtools MCP `evaluate_script` tool.

Caveat: overrides live inline on `<html>` plus the managed style tag, persisted to `localStorage.themeLabOverrides` and re-applied on re-injection. Reset clears everything; a hard reload clears the DOM overrides but not localStorage. The × close button keeps overrides applied.
